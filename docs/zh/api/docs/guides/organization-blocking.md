# API 组织屏蔽

> 完整文档索引请参见 [llms.txt](/llms.txt)。可通过在页面 URL 末尾追加 `.md` 来获取文档页面的 Markdown 版本。

API 组织封锁允许你限制用户从你的网络访问哪些 API 组织。通过你的代理或安全访问服务边缘（SASE）服务配置一个组织 ID 的允许列表。

## 工作原理

- **自定义允许列表请求头：** 你可以通过添加一个自定义 HTTP 请求头来配置要允许的 API 组织， `OpenAI-Allowed-Organization-Ids`，到你的网络配置中。你可以指定一个或多个组织 ID（例如， `org-…`）放在该请求头中，用英文逗号分隔，不要带空格。
- **API 平台强制执行允许列表：**
  - 当用户从你的网络登录到 API 平台时，OpenAI 会读取该请求头，并检查用户尝试访问的 API 组织是否与请求头中列出的某个组织 ID 匹配 `OpenAI-Allowed-Organization-Ids` 。
  - 如果用户尝试访问未在请求头中列出的组织，OpenAI 会自动拒绝该请求，并返回状态码为 `403`，的错误，从而阻止对该组织的访问。只有请求头中列出的组织才可被访问。

## 设置

### 步骤 1：查找你的组织 ID

若要允许特定组织访问，请复制你要允许的每个组织的组织 ID。你可以在 API 平台的 Organization 设置页面找到该 ID：

- 登录你的 API Platform 账号并切换到目标组织。
- 进入组织设置页面，记录 Organization ID（示例值： `org-Tkxfm8owx4zIPaJGNDVrPs6m`).

### 第 2 步：配置请求头

客户应通过网络代理或安全访问服务边缘（SASE）服务配置其网络，以发送该请求头。

- **如需允许多个组织**，请使用英文逗号分隔各组织 ID，且不要添加空格。
- **指定 URL 定向：**
  - 将你的代理或 SASE 服务配置为仅对发往以下地址的请求应用该标头 `https://api.openai.com/*`.

### 步骤 3：验证配置

配置好请求头后，从连接到规则所适用网络的设备上测试访问。

1. 使用同时拥有以下两者访问权限的账号登录 API Platform：
   - 一个包含在允许列表中的组织。
   - 一个未包含在允许列表中的组织。
2. 打开包含在允许列表中的组织，确认你可以访问它。
3. 尝试打开未包含在允许列表中的组织，确认访问被阻止且错误的状态码为 `403`.
4. 如果你允许多个组织，确认你可以访问每一个组织。

如果结果与预期不符，请检查你的代理或 SASE 规则是否应用于测试设备，并确认标头中包含正确的组织 ID。

### 排查访问错误

- **状态码 403：** 如果用户尝试访问API中未被授权的组织，则会看到错误。该错误的状态码为 `403`，并提示一条消息，表明用户无权访问该组织。
- **状态码 400：** 如果请求头值格式不正确（例如，组织 ID 无效），则所有带有该请求头的请求都会失败，并返回状态码为 `400`.
