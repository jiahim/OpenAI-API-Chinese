## Rule model

| 部分                  | 用途                                                         |
| --------------------- | --------------------------------------------------------------- |
| 提供方              | 定义 该公司 信任的颁发方与签名密钥。OpenAI              |
| 工作区             | 将生成的访问权限限制在一个托管的 ChatGPT 工作区内。   |
| 主体             | 在该工作区中选择一个现有用户或服务账户。 |
| 身份检查       | 限制哪些已验证的身份令牌可使用该规则。       |
| 作用域                | 可选择性地收窄现有的 Codex OAuth 作用域。              |
| 访问令牌有效期 | 将 OpenAI 访问令牌限制为 60 至 3,600 秒。     |

主体及其工作区成员身份必须在交换之前就已存在。规则不会在
工作负载连接时创建用户、服务账户或成员身份。

## 身份检查如何组合

规则可以使用以下检查：

| 检查              | 行为                                                              | 用于                                               |
| ------------------ | --------------------------------------------------------------------- | -------------------------------------------------------- |
| 主体            | 精确 `sub` 值或一个结尾 `*` 前缀。                         | 一个工作负载身份或受控的主体命名空间。 |
| 可接受的受众 | 一到 32 个受众字符串。令牌必须至少包含一个。 | 专门为 OpenAI 颁发的令牌。                   |
| 精确声明       | 最多 32 个精确的顶层标量声明值。                         | 稳定的字符串、数字、true/false 值或 null。     |
| CEL 条件      | 基于名为 `assertion`.   | 列表、嵌套声明或一组允许的值。        |

至少设置一个 subject、exact-claim 或 CEL 检查。仅指定已接受的
受众并不能标识工作负载。如果你配置了多种
检查类型，则每种都必须通过。

提供方验证先行。规则不能覆盖提供方的
颁发者、签名、过期时间、断言生命周期、重放或提供方级 CEL
检查。

## 主题匹配

当某个稳定的主题能够标识工作负载时，请使用完全匹配的主题 `sub` ：

```text
repo:example-company/payments:environment:production
```

以一个结尾 `*` 执行前缀匹配：

```text
system:serviceaccount:production:codex-*
```

通配符必须是最后一个字符，并且必须位于非空前缀之后。
OpenAI 不接受 `*`, `repo:*:production`、或 `repo/*/main`.

当存在更稳定的声明可以区分特权工作负载时，请不要使用过于宽泛的前缀。例如，GitHub 规则应匹配仓库、
工作流 文件、ref 或受保护环境，而不是匹配某一个组织拥有的所有仓库，
工作流 文件、ref 或受保护环境，而不是匹配某一个组织拥有的所有仓库
。

## 精确断言

精确声明在不转换类型的情况下比较顶层 JWT 声明。字符串
仅匹配相同的字符串，布尔值仅匹配相同的布尔值，
数字仅匹配相同的数值。列表和对象不支持作为精确值
。

例如：

```json
{
  "repository": "example-company/payments",
  "ref": "refs/heads/main",
  "environment": "production"
}
```

不要将 `sub` 包含在 exact-claims 映射中。请使用 subject 字段或 CEL。
对嵌套的提供方声明和列表成员关系使用 CEL。

## CEL 条件

CEL 条件接收完整的已验证 JWT 声明映射作为 `assertion` 并
必须返回 `true` 或 `false`。OpenAI 支持有界 CEL 子集，因此规则
求值保持可预测。

若要在一个规则中允许一组精确的 subject：

```text
assertion.sub in [
  "repo:example-company/payments:environment:production",
  "repo:example-company/billing:environment:production"
]
```

若要求一个仓库以及两个 ref 之一：

```text
assertion.repository == "example-company/payments" &&
assertion.ref in ["refs/heads/main", "refs/heads/release"]
```

若要读取嵌套或可选的声明：

```text
has(assertion.environment) &&
assertion.environment == "production"
```

支持以下辅助函数： `has`, `size`, `contains`, `startsWith`，以及
`endsWith`。正则表达式匹配、集合迭代宏（如
`all` 或 `exists`）、任意函数以及除 `assertion`
之外的标识符均不受支持。表达式应保持简洁，在能表达相同策略时优先使用精确比较。
当可以表达相同的策略时，

若声明缺失、操作不受支持、结果非布尔或求值出错，则
拒绝该交换。

## 受众匹配

提供者可以设置一个预期的受众。规则也可以改为设置一个或多个
可接受的受众。当规则包含受众列表时，列表中至少有一个值必须与
令牌 `aud` 声明必须出现在该列表中。

当你的提供商支持专用受众时,请为 OpenAI 使用专用受众。SPIFFE
JWT-SVID 规则必须设置一个已接受的受众。如果 OIDC 提供方未定义提供商级别的受众，那么 OIDC 规则也必须设置一个受众。
提供商级别的受众，则 OIDC 规则也必须设置一个受众。

受众匹配与身份检查是累积生效的。一个通过匹配的受众不能
弥补未通过的主题、精确声明或 CEL 检查。

## Principal cardinality

一条规则对应一个主体：

```text
many accepted external identities -> one federation rule -> one OpenAI principal
```

这支持工作负载副本、任务或经批准的主体以相同身份执行
用户或服务账号。它不允许一条规则根据声明选择不同的
主体。当工作负载需要不同的主体时，请创建单独的规则
主体、工作区、作用域或令牌生命周期。

多条规则可以针对同一主体。当你需要对每个工作负载进行独立的生命周期
控制或需要更清晰的可审计归属时，请使用多条独立的规则。

## 作用域与授权

该规则可以缩小已颁发访问令牌中的 OAuth 作用域范围，但无法授予
目标主体或工作区尚未拥有的权限。

省略作用域时，OpenAI 会使用标准的 Codex 作用域： `openid`,
`profile`, `email`，以及 Codex 本地访问权限。如果你通过 Admin
API 设置作用域，请包含 `chatgpt.workspace.feature.allow-codex-local-access.access` 并仅使用
这四个受支持的值。

首先选择权限最小的主体和工作区权限。将
规则作用域视为第二层限制，而非主要的授权边界。

## Token 生命周期

将 OpenAI 访问令牌的生命周期设置为 60 到 3,600 秒。OpenAI 使用
以下两者中的较短者：

- 上游身份令牌的剩余有效期。
- 该规则所配置的访问令牌有效期。

较短的生命周期会减少已签发 token 在策略修改后仍能继续使用的时间，
但会增加交换频率。10 分钟的生命周期是一个实用的起始
值，除非你的工作负载需要不同的平衡。

## 重放保护

提供方级的重放保护使用 JWT `jti` 声明。当管理员
启用 **Prevent assertion replay** 且令牌具有非空的 `jti`, OpenAI
会接受该断言 `jti` 在该提供方上仅使用一次，直到该断言过期为止。

工作负载必须在每次交换之前获取一个具有新的 `jti` 的断言，
包括在结果未知的交换之后进行重试。没有
`jti` 的断言仍然可用，但不会获得重放保护。为空、null 或
非字符串 `jti` 的值无法通过校验。

## 变更、停用与归档

对身份校验、作用域或令牌生命周期的常规编辑会应用于新的交换。
编辑之前签发的访问令牌可以保持有效，直至其现有 TTL
结束。

禁用某个规则或提供商会阻止新的交换，并撤销通过该规则或提供商签发的 OpenAI 访问
令牌。归档的效果与此相同，且不可撤销。
更改提供者信任设置（如颁发者或 JWKS 设置）会撤销已颁发的令牌，
该撤销会在新的信任配置生效之前完成。

在紧急停止或临时暂停时使用禁用功能。归档资源
仅在你不再需要它时进行。
