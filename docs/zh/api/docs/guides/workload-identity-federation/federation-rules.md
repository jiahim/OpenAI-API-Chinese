# Codex 联合规则参考

> 如需查看完整的文档索引，请参阅 [llms.txt](/llms.txt)。文档页面的 Markdown 版本可通过在页面 URL 后追加 `.md` 来获取。

联合规则决定哪些经过验证的工作负载身份可以充当
ChatGPT 用户或服务账户。OpenAI 仅评估由
Codex 进程指定的规则。它不会搜索每条规则以查找匹配项。

每条规则有一个目标主体，并且可以接受一个或多个上游
身份。要在一条规则中接受一组主体，请使用尾部前缀
主体或 CEL 条件。你也可以为同一主体创建多条规则
。

有关设置步骤，请参阅 [将工作负载身份与
Codex](https://developers.openai.com/codex/enterprise/workload-identity)。一起使用。要使用代码管理规则，请参阅
[工作负载身份管理
API](https://developers.openai.com/api/docs/guides/workload-identity-federation/admin-api).

## 规则模型

| 部分                  | 用途                                                         |
| --------------------- | --------------------------------------------------------------- |
| 提供方              | 定义 OpenAI 信任的签发方和签名密钥。              |
| 工作区             | 将生成的访问权限限制为一个受管理的 ChatGPT 工作区。   |
| 主体             | 选择该工作区中的一个现有用户或服务账号。 |
| 身份检查       | 限制哪些经过验证的身份令牌可以使用该规则。       |
| 范围                | 可选择性地缩小现有的 Codex OAuth 范围。              |
| 访问令牌有效期 | 将 OpenAI 访问令牌限制为 60 至 3,600 秒。     |

主体及其工作区成员资格必须在交换之前存在。一条规则
在工作负载连接时不会创建用户、服务账户或成员资格。

## 身份检查如何组合

规则可以使用这些检查：

| 检查              | 行为                                                              | 用途                                               |
| ------------------ | --------------------------------------------------------------------- | -------------------------------------------------------- |
| 主题            | 精确的 `sub` 值或一个尾部 `*` 前缀。                         | 一个工作负载身份或受控的主题命名空间。 |
| 接受的受众 | 1 到 32 个受众字符串。令牌必须至少包含一个。 | 专门为 OpenAI 铸造的令牌。                   |
| 精确声明       | 最多 32 个精确的顶级标量声明值。                         | 稳定的字符串、数字、true/false 值或 null。     |
| CEL 条件      | 一个针对已验证声明映射命名的布尔表达式 `assertion`.   | 列表、嵌套声明或一组允许的值。        |

至少设置一个主体、精确声明或 CEL 检查。仅接受
受众本身并不能识别工作负载。如果配置了多个
检查类型，则每一项都必须通过。

提供商验证首先进行。规则不能覆盖提供商的
签发者、签名、过期时间、断言生命周期、重放或提供商级 CEL
检查。

## 主题匹配

只要存在一个稳定的确切主体，就使用该确切主体， `sub` 用以标识工作负载：

```text
repo:example-company/payments:environment:production
```

末尾的 `*` 执行前缀匹配：

```text
system:serviceaccount:production:codex-*
```

通配符必须是最后一个字符，并且必须跟在非空前缀之后。
OpenAI 不接受 `*`, `repo:*:production`，或 `repo/*/main`.

当更稳定的声明可以区分特权工作负载时，不要使用宽泛前缀。
例如，GitHub 规则应匹配仓库、
工作流 文件、引用或受保护环境，而不是某个组织拥有的每个仓库
。

## 精确表述

精确匹配比较顶层 JWT 声明，而不转换其类型。
字符串仅匹配相同字符串，布尔值仅匹配相同布尔值，
数字匹配相同的数值。列表和对象不支持
作为精确匹配值。

例如：

```json
{
  "repository": "example-company/payments",
  "ref": "refs/heads/main",
  "environment": "production"
}
```

不要在 `sub` 精确声明映射中包含。使用 subject 字段或 CEL。
对于嵌套的提供商声明和列表成员资格，请使用 CEL。

## CEL 条件

CEL 条件会接收完整的已验证 JWT 声明映射作为 `assertion` 并且
必须返回 `true` 或 `false`。 OpenAI 支持受限的 CEL 子集，因此规则
求值保持可预测。

要在一项规则中允许一组精确的主题：

```text
assertion.sub in [
  "repo:example-company/payments:environment:production",
  "repo:example-company/billing:environment:production"
]
```

要要求一个仓库和两个引用之一：

```text
assertion.repository == "example-company/payments" &&
assertion.ref in ["refs/heads/main", "refs/heads/release"]
```

要读取嵌套或可选的声明：

```text
has(assertion.environment) &&
assertion.environment == "production"
```

支持的辅助函数包括 `has`, `size`, `contains`, `startsWith`，以及
`endsWith`。正则表达式匹配、集合迭代宏，例如
`all` 或 `exists`，任意函数，以及除 `assertion`
之外的标识符均不受支持。保持表达式简短，并在可以用精确检查表达相同策略时优先使用精确检查
。

缺失的声明、不受支持的操作、非布尔结果或求值错误
会拒绝交换。

## 受众匹配

提供方可以设置一个预期受众。规则也可以改为设置一个或多个
可接受的受众。当规则带有受众列表时，令牌中至少有一个值
的 `aud` 声明必须出现在该列表中。

当你的提供方支持时，为OpenAI使用专用受众。SPIFFE
JWT-SVID规则必须设置一个可接受的受众。如果提供方未定义提供方级别的受众，OIDC规则也必须设置一个。
如果提供方未定义提供方级别的受众，OIDC规则也必须设置一个。

受众匹配和身份检查是累积性的。匹配的受众并
不能弥补未通过的主体、精确声明或CEL检查。

## 主体基数

一条规则恰好映射到一个主体：

```text
many accepted external identities -> one federation rule -> one OpenAI principal
```

这支持工作负载副本、作业或经批准的主体充当同一
用户或服务账户。它不允许一条规则根据声明选择不同的
主体。当工作负载需要不同的主体、工作区、作用域或令牌生命周期时，请创建单独的规则。
主体、工作区、作用域或令牌生命周期。

多条规则可以针对同一主体。当你需要独立的生命周期控制或更清晰的审计归属时，请使用单独的规则。
独立的生命周期控制或更清晰的审计归属，请为每个工作负载使用单独的规则。

## 范围与授权

该规则可以缩小颁发的访问令牌中的 OAuth 范围。它不能授予
目标主体或工作区尚未拥有的权限。

当你省略范围时，OpenAI 使用标准 Codex 范围： `openid`,
`profile`, `email`，以及 Codex 本地访问。如果你通过 Admin
API 设置范围，请包含 `chatgpt.workspace.feature.allow-codex-local-access.access` 并使用
仅那四个受支持的值。

首先选择最小权限的主体和工作区权限。将
规则范围视为第二层限制，而非主要授权边界。

## 令牌有效期

设置 OpenAI 访问令牌的生命周期，范围为 60 至 3,600 秒。OpenAI 采用
两者中较短的一个：

- 上游身份令牌的剩余生命周期。
- 规则配置的访问令牌生命周期。

较短的有效期可以减少已签发令牌在策略编辑后仍然有效的时间，
但会增加交换频率。10 分钟的有效期是一个实用的起点，
除非你的工作负载需要不同的平衡。

## 重放保护

提供商级别的重放保护使用 JWT `jti` 声明。当管理员
启用 **防止断言重放** 并且令牌具有非空的 `jti`，时， OpenAI
接受该 `jti` 仅在该提供商处使用一次，直到断言过期。

工作负载必须获取带有新 `jti` 的新断言，用于每次交换，
包括在结果未知的交换后进行重试。没有
`jti` 的断言仍然可用，但不获得重放保护。空的、null 或
非字符串 `jti` 值无法通过验证。

## 变更、禁用与存档

对身份检查、范围或令牌生命周期的常规编辑适用于新的交换。
编辑前签发的访问令牌在其现有 TTL
结束前仍可保持有效。

禁用规则或提供程序会阻止新的交换并撤销通过其签发的 OpenAI 访问
令牌。归档也会执行相同操作，且无法撤销。
更改提供程序信任设置（如颁发者或 JWKS 设置）会在新信任配置生效前撤销已签发的令牌
，再激活新的信任配置。

将禁用用于紧急停止或临时暂停。仅在不再需要资源时才进行归档
。

## 限制

| 资源                                | 限制               |
| --------------------------------------- | ------------------- |
| 每个组织的非归档提供方 | 50                  |
| 每个提供方的非归档规则         | 50                  |
| 每条规则的精确声明                   | 32                  |
| 每条规则的接受受众             | 32 个唯一值    |
| 主题长度                          | 4,096 字节         |
| 精确声明映射或 CEL 条件        | 16 KiB              |
| 访问令牌生命周期                   | 60 至 3,600 秒 |

为需要独立签发者（issuer）、
密钥、重放或生命周期控制的信任边界创建单独的提供程序。对于共享信任但需要不同主体或访问策略的工作负载，
在同一提供程序下创建单独的规则。
