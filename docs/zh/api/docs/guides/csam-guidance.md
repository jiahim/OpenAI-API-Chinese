## 构建时关注儿童安全

OpenAI 对开发者有明确的儿童安全期望：
你负责确保你的用户在合规的情况下使用 OpenAI 服务，
其中包括将儿童性虐待和剥削定为犯罪的法律。切勿使用 OpenAI 服务去剥削、危害或
sexualize anyone under the age of 18. Never use 该公司 services to exploit, endanger, or
性化任何未满 18 周岁的人。请参阅 OpenAI 。

网络儿童性剥削和虐待会影响一系列产品和服务，
其中也包括那些不以儿童为目标用户的产品和服务。OpenAI 希望帮助
开发者了解应采取哪些措施来应对此类滥用行为。

尽早考虑人们可能如何滥用你的产品。
从早期开始，让儿童安全防护措施能够随你的业务一起扩展，而不是在事后才尝试
将其改造进已经复杂的产品或系统中。
各种规模的开发团队和组织都应评估人们可能如何
将其产品滥用于一系列危害，包括儿童性虐待材料
(CSAM)、诱骗、性勒索、儿童性化、直播
虐待，以及人口贩运——尤其当其产品支持消息、内容
上传、图像编辑、直播、发现或支付功能时。

本资源重点关注 CSAM，并为开发者提供切实可行的指导，以
保护儿童。

### 规模化防护措施

合适的控制措施和安全防护取决于产品、其开发阶段
和成熟度、其用户和功能、其运营所在的地区，以及其可用
资源。

风险敞口较大的产品——例如那些支持
直播、图像生成或编辑、文件存储或私有
连接的产品——应考虑实施并加强以下安全防护：

- 在产品上线前以及任何高风险功能发生变更时进行产品风险评估。
  See .
- 与所提供服务相匹配的分层检测，可能包括哈希匹配、
  图像或视频分类器、文本信号、关键词检测以及 URL 拦截。
- 对高置信度或高严重程度的信号进行人工审核，并使用相关工具
  保障审核人员的福祉，避免其不必要地接触有害
  内容。
- 通过速率限制、账户管控和滥用监测，增加重复滥用的
  难度。
- 定期开展测试与度量，以便发现漏洞、跟踪效果并
  改进你的各项管控措施。

这些建议只是一个起点，并非法律意见或普适的
护理标准。请结合你的服务、风险状况以及适用法律进行调整。
