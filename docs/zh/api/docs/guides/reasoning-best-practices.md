# 推理最佳实践

OpenAI 提供两种类型的模型： [推理模型](https://developers.openai.com/api/docs/models#o4-mini) （例如 o3 和 o4-mini）以及 [GPT 模型](https://developers.openai.com/api/docs/models#gpt-4.1) （如 GPT-4.1）。这些模型系列的行为有所不同。

本指南涵盖：

1. 我们的推理模型与非推理 GPT 模型之间的区别
1. 何时使用我们的推理模型
1. 如何有效提示推理模型

了解更多关于 [推理模型](https://developers.openai.com/api/docs/guides/reasoning) 以及它们的工作方式。

## 推理模型与 GPT 模型

与 GPT 模型相比，我们的 o 系列模型擅长处理不同的任务，并且需要不同的提示词。这两个模型家族并无优劣之分——它们只是各有所长。

我们训练 o 系列模型（“规划者”）更深入、更持久地思考复杂任务，使它们在制定策略、规划复杂问题解决方案以及基于大量模糊信息做出决策方面表现出色。这些模型还能以高准确度和精确度执行任务，因此非常适合通常需要人类专家参与的领域，如数学、科学、工程、金融和法律服务。

另一方面，我们延迟更低、成本效益更高的 GPT 模型（“主力军”）则专为直接执行而设计。应用程序可能会使用 o 系列模型来规划解决问题的策略，并使用 GPT 模型来执行具体任务，特别是在速度和成本比完美准确性更重要的情况下。

### 如何选择

对你的用例来说，什么最重要？

- **速度与成本** → GPT 模型速度更快，且往往成本更低
- **执行已明确定义的任务** → GPT 模型能很好地处理明确定义的任务
- **准确性与可靠性** → o 系列模型是可靠的决策者
- **复杂问题求解** → o 系列模型能处理模糊性与复杂性

如果速度和成本是完成任务时最重要的因素 _且_ 你的用例由直接、定义明确的任务组成，那么我们的 GPT 模型最适合你。然而，如果准确性和可靠性是最重要的因素 _且_ 你需要解决一个非常复杂的多步骤问题，那么我们的 o-series 模型可能适合你。

大多数 AI 工作流会同时使用这两种模型——o-series 用于智能体规划和决策，GPT 系列用于任务执行。

![GPT 模型与 o-series 模型搭配良好](https://cdn.openai.com/API/docs/images/customer-service-example.png)




_我们的 GPT-4o 和 GPT-4o mini 模型对订单详情和客户信息进行分类，识别订单问题和退货政策，然后将所有这些数据点输入 o3-mini，以根据政策对退货可行性做出最终决定。_




## 何时使用我们的推理模型

以下是我们从客户及 OpenAI 内部观察到的一些成功使用模式。这并不是对所有可能用例的全面综述，而是对我们 o 系列模型进行测试的一些实用指导。

[准备好使用推理模型了吗？直接进入快速入门 →](https://developers.openai.com/api/docs/guides/reasoning)

### 1. 处理模糊任务

推理模型特别擅长利用有限的信息或零散的信息片段，在简单的提示下，理解用户的意图并处理说明中的任何空缺。实际上，推理模型通常会在做出无根据的猜测或尝试填补信息空白之前提出澄清性问题。

> “o1 的推理能力使我们的多智能体平台 Matrix 在处理复杂文档时能够生成详尽、格式良好且详细的响应。例如，o1 使 Matrix 能够通过基本提示轻松识别信贷协议中受限支付能力下的可用篮子。没有其他模型能达到这样的性能。在密集的信贷协议上，与其他模型相比，o1 在 52% 的复杂提示上产生了更强的结果。”
>
> —[Hebbia](https://www.hebbia.com/)，一家面向法律和金融领域的人工智能知识平台公司

### 2. 大海捞针

当你传递大量非结构化信息时，推理模型擅长理解并提取最相关的信息来回答问题。

> "为了分析一家公司的收购案，o1 审阅了数十份公司文件（如合同和租约），以找出可能影响交易的任何棘手条款。该模型的任务是标记关键条款，并在此过程中发现了脚注中一项关键的"控制权变更"条款：如果公司被出售，它必须立即偿还一笔 7500 万美元的贷款。o1 对细节的极致关注使我们的 AI 智能体能够通过识别关键信息来支持金融专业人士。"
>
> —[Endex](https://endex.ai/)，AI 金融情报平台

### 3. 在大型数据集中发现关联和细微差别

我们发现推理模型特别擅长对包含数百页密集、非结构化信息的复杂文档进行推理，例如法律合同、财务报表和保险索赔。这些模型特别擅长在不同文档之间建立关联，并根据数据中隐含的真相做出决策。

> “税务研究需要综合多份文档，才能得出最终且令人信服的答案。我们将 GPT-4o 替换为 o1，发现 o1 在推理文档之间的相互作用方面表现得更好，能够得出在单一文档中并不明显的逻辑结论。因此，通过切换到 o1，端到端性能提升了 4 倍——这令人难以置信。”
>
> —[Blue J](https://www.bluej.com/)，税务研究 AI 平台

推理模型还擅长对细微的策略和规则进行推理，并将其应用于手头任务，以得出合理的结论。

> “在财务分析中，分析师经常要处理涉及股东权益的复杂情景，并需要了解相关的法律细节。我们用来自不同提供商的约 10 个模型测试了一个具有挑战性但常见的问题：融资如何影响现有股东，尤其是当他们行使反稀释特权时？这需要推理投资前和投资后的估值，并处理循环稀释循环——顶尖财务分析师需要花 20-30 分钟才能弄清楚。我们发现 o1 和 o3-mini 可以完美地做到这一点！模型甚至生成了一个清晰的计算表，显示了对 10 万美元股东的影响。”
>
> –[BlueFlame AI](https://www.blueflame.ai/)，投资管理 AI 平台

### 4. 多步骤智能体规划

推理模型对于智能体规划和策略制定至关重要。我们观察到，将推理模型用作“规划者”，为问题生成详细的多步骤解决方案，然后根据每一步是高智能还是低延迟更重要，选择并指派合适的 GPT 模型（“执行者”），这种做法取得了成功。

> “我们在智能体基础设施中使用 o1 作为规划器，让它编排工作流中的其他模型以完成多步骤任务。我们发现 o1 非常擅长选择数据类型并将大问题分解为更小的部分，使其他模型能够专注于执行。”
>
> —[Argon AI](https://argon-ai.com/)，面向制药行业的 AI 知识平台

> “o1 为我们在 Lindy（我们的工作 AI 助手）中的许多智能体工作流提供支持。该模型使用函数调用从你的日历或电子邮件中提取信息，然后可以自动帮你安排会议、发送电子邮件以及管理日常任务的其他部分。我们将所有曾经出问题的智能体步骤都切换到了 o1，并观察到我们的智能体几乎一夜之间变得完美无瑕！”
>
> —[Lindy.AI](http://Lindy.AI)，工作 AI 助手

### 5. 视觉推理

截至目前，o1 是唯一支持视觉能力的推理模型。它与 GPT-4o 的区别在于，o1 能够理解最具挑战性的视觉内容，例如结构模糊的图表和表格，或图像质量不佳的照片。

> “我们为在线数百万种产品自动化风险与合规审查，包括奢侈品珠宝仿品、濒危物种和管制物质。在我们最难的图像分类任务上，GPT-4o 达到了 50% 的准确率。o1 在我们未对流程做任何修改的情况下，取得了 88% 的惊人准确率。”
>
> —[SafetyKit](https://www.safetykit.com/), 人工智能驱动的风险与合规平台

根据我们内部测试，我们发现 o1 能够从高度详细的建筑图纸中识别固定装置和材料，以生成全面的材料清单。我们观察到的最令人惊讶的一点是，o1 可以通过提取建筑图纸某一页上的图例，并在没有明确指令的情况下将其正确应用到另一页，从而在不同图像之间建立关联。下面你可以看到，对于 4x4 PT 木柱，o1 根据图例识别出“PT”代表防腐处理（pressure treated）。

### 6. 审查、调试和改进代码质量

推理模型在审查和改进大量代码方面尤为有效，鉴于模型延迟较高，它们通常会在后台运行代码审查。

> “我们在 GitHub 和 GitLab 等平台上提供自动化 AI 代码审查。虽然代码审查过程本身对延迟不敏感，但它确实需要理解跨多个文件的代码差异。这正是 o1 的突出之处——它能够可靠地检测出人工审查员可能遗漏的代码库细微更改。切换到 o 系列模型后，我们的产品转化率提升了 3 倍。”
>

> “o3-mini 持续生成高质量、结论性的代码，并且在问题定义明确时，即使面对极具挑战性的编码任务，也经常能得出正确的解决方案。虽然其他模型可能只适用于小规模、快速的代码迭代，o3-mini 在规划和执行复杂软件设计系统方面表现出色。”
>

### 7. 对其它模型响应的评估与基准测试

我们还看到推理模型在基准测试和评估其他模型响应方面表现出色。数据验证对于确保数据集的质量和可靠性至关重要，尤其是在医疗保健等敏感领域。传统验证方法使用预定义规则和模式，但像 o1 和 o3-mini 这样的先进模型能够理解上下文并推理数据，从而采用更灵活、更智能的方式进行验证。

> “许多客户在 Braintrust 的评估流程中使用 LLM 作为评判者。例如，一家医疗保健公司可能会使用像 gpt-4o 这样的主力模型来总结患者问题，然后用 o1 评估摘要质量。一位 Braintrust 客户发现，评判者的 F1 分数从使用 4o 时的 0.12 提升到使用 o1 时的 0.74！在这些用例中，他们发现 o1 的推理能力在处理最困难、最复杂的评分任务时，能够发现补全中的细微差异，这堪称革命性的改变。”
>
> —[Braintrust](https://www.braintrust.dev/)，AI 评估平台

## 如何有效提示推理模型

这些模型在处理直接明了的提示时表现最佳。某些提示工程技巧，比如指示模型"逐步思考"，可能不会提升性能（有时甚至会妨碍性能）。请参阅下面的最佳实践，或 [开始了解提示示例](https://developers.openai.com/api/docs/guides/reasoning#advice-on-prompting).

- **开发者消息是新的系统消息**：从 `o1-2024-12-17`开始，推理模型支持开发者消息而非系统消息，以符合 [模型规范](https://cdn.openai.com/spec/model-spec-2024-05-08.html#follow-the-chain-of-command).
- **保持提示词简单直接**：模型擅长理解并响应简洁、清晰的指令。
- **避免链式思维提示词**：由于这些模型在内部进行推理，因此提示它们“逐步思考”或“解释推理过程”是不必要的。
- **使用分隔符以增强清晰度**：使用 Markdown、XML 标签和章节标题等分隔符来清晰地标示输入的不同部分，帮助模型恰当解读各个部分。
- **先尝试零样本，必要时再尝试少样本**：推理模型通常不需要少样本示例就能产生良好结果，因此先尝试不包含示例的提示词。如果你对期望输出有更复杂的要求，可能有助于在提示词中包含一些输入和期望输出的示例。请确保示例与提示词指令非常吻合，因为两者之间的差异可能导致不佳结果。
- **提供具体指南**：如果你明确希望约束模型响应（例如“提出预算低于 500 美元的解决方案”），请在提示词中明确列出这些约束。
- **明确最终目标**：在你的指令中，尝试为成功响应提供非常具体的参数，并鼓励模型持续推理和迭代，直到符合你的成功标准。
- **Markdown 格式**：从 `o1-2024-12-17`开始，API 中的推理模型将避免生成带 Markdown 格式的响应。若要向模型表明你希望在响应中包含 Markdown 格式，请在开发者消息的第一行包含字符串 `Formatting re-enabled` 。

## 如何保持低成本和高准确性

随着 `o3` 和 `o4-mini` 模型的推出，Responses API 中持久化的推理项被区别对待。此前（对于 `o1`, `o3-mini`, `o1-mini` 和 `o1-preview`），推理项在后续的 API 请求中始终被忽略，即使它们被包含在请求的输入项中。随着 `o3` 和 `o4-mini`的出现，与函数调用相邻的一些推理项会被包含在模型的上下文中，以帮助提升模型性能，同时使用最少的推理令牌。

为了在此变更下获得最佳效果，我们建议使用 [Responses API](https://developers.openai.com/api/reference/resources/responses) 并配合 `store` 参数设置为 `true`，同时传入先前请求中的所有推理项（要么使用 `previous_response_id`，要么从旧请求中取出所有输出项并将其作为新请求的输入项传入）。OpenAI 会自动将任何相关的推理项包含在模型的上下文中，并忽略无关的推理项。在更高级的用例中，如果你希望更精确地管理模型上下文中的内容，我们建议你至少包含最近一次函数调用与先前用户消息之间的所有推理项。这样做将确保模型在响应函数调用时不必重新开始推理，从而带来更好的函数调用性能和更低的总令牌使用量。

如果你使用的是 Chat Completions API，推理项永远不会包含在模型的上下文中。这是因为 Chat Completions 是一个无状态的 API。在涉及许多函数调用的复杂智能体场景中，这将导致模型性能略有下降，并增加推理令牌的使用量。在不涉及复杂多函数调用的场景中，无论使用哪个 API，性能都不会有下降。
