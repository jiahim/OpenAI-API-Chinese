# 追踪

> 完整文档索引请参阅 [llms.txt](/llms.txt)。文档页面的 Markdown 版本可通过在页面 URL 后追加 `.md` 获取。

一个 **会话** 让你的 智能体 的对话和工作保持在一起。一个会话可以包含多个 **轮次**，每一轮都是一次工作循环。一个 **追踪** 展示了一轮内的各个步骤：模型响应、工具调用，以及委派给其他 智能体 的工作。

该 [追踪 仪表板](https://platform.openai.com/logs?api=agents) 展示你的 智能体 所做的事情，包括每个步骤记录的输入、输出、耗时和状态。

如需通过 API 获取会话状态、实时事件、保存的输出和使用情况，请从 [可观测性](https://developers.openai.com/api/docs/guides/agents-api/observability).

新会话默认启用追踪。公共测试版 API 未暴露 追踪 配置或外部 追踪 导出器。

## 打开 追踪

1. 打开 [日志 → 智能体](https://platform.openai.com/logs?api=agents) ，然后选择你运行 智能体 的项目。
2. 使用 **搜索日志**。查找你的会话。使用 **添加筛选条件** 按模型、状态或日期进行筛选。
3. 选择该会话以打开其时间线和轮次列表。
4. 展开某个轮次，然后在时间线或事件列表中选择一个步骤以查看其详细信息。

会话摘要会显示其状态、模型、开始时间、最近活动时间、对话轮次以及已记录的 token 用量。

## 读取追踪

从会话入手，然后逐步进入轮次：

1. **Session：** Logs → 智能体 中的每一项都是一个会话。打开它即可查看其时间线和对话轮次列表。例如，用户可以先询问订单相关问题，然后在同一会话中提出后续问题。
2. **Turn：** 展开某个轮次即可查看该周期内完成的工作。一个轮次可以包含多个模型响应和工具调用。在该轮次结束后发送的后续消息会在同一会话中开启另一个轮次。
3. **轮次内的步骤：** 追踪 会将模型响应和工具调用归组到执行它们的根 智能体 或子智能体下。每个被记录的步骤称为一个 **span**.

选择一个片段以查看其状态、持续时间、开始和结束时间以及记录的数据：

| Select                                           | 可检查的内容                                                           |
| ------------------------------------------------ | ------------------------------------------------------------------------------ |
| [**智能体**](#agent)                              | 智能体的详细信息、指令以及记录的 token 用量                    |
| [**生成**](#generation) （模型响应） | 模型响应的输入和输出记录                             |
| [**工具**](#tool)                                | 调用了哪个工具、传递给它的参数以及可用时的结果 |

### 智能体

一个 智能体 跨度对完成的工作进行分组，这些工作由 **根 智能体** 或一个 **子智能体**：执行：另一个被要求处理部分任务的 智能体。模型响应和工具调用会显示在执行它们的 智能体 下。

详情面板显示：

- **智能体 类型：** 根 智能体（`root`）或子智能体（`subagent`).
- **智能体：** 记录时的 ID、名称、模型和指令。
- **用量：** 该 智能体 记录的令牌计数。这些计数仅涵盖该 智能体 本身，不包括其子智能体。
- **耗时** 和 **结果状态：** 记录的工作耗时及其是已完成、失败还是未完成。

### 生成

生成跨度（generation span）将记录的模型输入和输出归为一组。每一轮对话可以包含多个生成。

在模型推理过程中，模型读取输入并生成响应。该响应可以请求工具。工具返回结果后，模型可以在新的生成中再产生一次响应。

- **Input：** 与该 response 关联的已记录输入，例如用户消息或工具结果。
- **Output：** 模型生成的已记录项，例如回答文本或工具调用。
- **Model：** 在记录时所使用的 response 对应模型。

### 工具

工具 span 描述一次工具调用及其记录的结果。

工具 span 包括对你自有函数的调用，以及对 **MCP（Model Context Protocol）** 服务器上的工具的调用。网页搜索和命令执行也可能以工具 span 的形式出现。

- **Call:** 工具请求，包括工具名称及参数（如有）。
- **Result:** 工具记录到的响应（如有）。
- **Outcome status** 和 **Error:** 记录到的结果及错误详情（如有）。

对于 MCP 工具调用， **Call** 包含服务器标签（`server_label`）、工具名称（`name`）和参数（`arguments`）。其响应和错误会在该处记录为 `output` 和 `error`（可用时）。单独的 **Result** 面板可能为空，因为 MCP 响应存储在 **Call**.

## 计时与状态

时间线会显示各个步骤的顺序以及哪些步骤是重叠的。 **放大** 可以更细致地查看较短的步骤。 **适应时间线** 可以查看整个会话。

每个 span 都会显示其持续时间和结果状态。失败的 span 还可以包含已记录的错误详情。

智能体 span 的持续时间包含其子步骤。步骤可能会重叠：两个子智能体同时运行 10 秒，总耗时大约也是 10 秒。

## Token 使用情况

**Tokens** 列在会话摘要中，用于展示会话用量。 **用量** 显示在某个智能体跨度中时，表示该智能体所记录的 token 数。

用量数据可能在轮次结束后才到达。出现空值或 `null` 表示该数值未知，并不代表该智能体使用了 0 个 token。随着更多用量数据变得可用，计数可能会变化，并且它不是最终账单。

## 当追踪就绪时

追踪会在一轮结束后构建完成。智能体 的回答可能会在其 追踪 或令牌用量准备好之前就已出现。

[实时会话事件](https://developers.openai.com/api/docs/guides/agents-api/sessions/events) 可在 智能体 仍在工作时显示进度。

## 示例：一个包含两个子智能体的轮次

本示例基于一段录制的会话。根智能体调用一个 MCP 工具,同时两个子智能体执行命令并获取文档。下文中的子智能体名称已简化,计数和耗时数据来自录制的追踪。

### 会话与轮次

会话页眉显示 **1 个回合**, **10 次工具调用**，以及 **252,468 个 token**。会话状态为 **空闲**，以及 **回合 1** 处于 **已完成** 状态，持续时长为 **1 分 37 秒**.

展开该回合会显示根 智能体及其子步骤。该追踪包含 **3 个 智能体 span** （根智能体和两个子智能体）， **11 个 generation span**，以及 **10 个 tool span**.

该树形结构将重复的生成和工具调用归组在一起，展示父子关系；时间线则显示每个步骤的运行时间。

```text
Session: Idle
└── Turn 1: Completed                              1m 37s
    └── Root agent                                1m 37s
        ├── 6 generations
        ├── 2 tools: spawn_agent_call
        ├── Subagent A                               24s
        │   ├── 2 generations
        │   └── Tool: command_execution               2s
        ├── Subagent B                               21s
        │   ├── 3 generations
        │   ├── 2 tools: notion.fetch              2s each
        │   └── Tool: send_input_call                 0ms
        ├── Tool: demo_capability_probe              87ms
        └── 3 tools: wait_for_agents_call
```

### 模型工作与委托

根 智能体 的第一次 **生成** 包含用户消息于 **Input**。其 **Output** 包含消息和两个 `spawn_agent_call` 条目。这些调用也会作为 **Tool** span 出现，产生的子智能体作为 **智能体** span 出现在根智能体下。

子智能体 A 有自己的生成和一次 `command_execution` 工具调用。子智能体 B 有三次生成、两次 `notion.fetch` MCP 调用和一次 `send_input_call`。它们的模型响应和工具分别属于各自的子智能体 span。

根 智能体 还有三个 `wait_for_agents_call` 工具 span。它最终的生成包含一条消息，记录的持续时间为 **6s**.

### MCP 工具调用

根 智能体 的 `demo_capability_probe` span 是一个已完成的 **Tool** span，持续时间为 **87ms**。其 **工具类型** 处于 `mcp_call`.

该 **Call** 面板包含以下字段：

```json
{
  "type": "mcp_call",
  "server_label": "demo_local",
  "name": "demo_capability_probe",
  "status": "completed"
}
```

以下片段展示了记录调用的一部分。同一面板包含其 `arguments` 以及位于 `output`。的 MCP 响应。独立的 **Result** 面板位于 `null`。该 span 的 **父级 span** 指向根 智能体。

子智能体 B 的两个 `notion.fetch` span 结构相同： `mcp_call` 作为工具类型，位于 **Call**，的 MCP 响应，以及作为其父级的子智能体。

### 本次会话中的计时与用量

两个子智能体的时间段在时间轴上存在重叠。子智能体 A 耗时 **24s** 并且 Subagent B 接管 **21s**，无论是在根 智能体 的 **1 分 37 秒** span 内。仪表盘会对这些显示的时长进行取整。

该 **用量** 每个 智能体 span 的面板都会显示其自身记录的令牌计数：

| 智能体      | 输入 token 数 | 输出 token 数 | 总 token 数 |
| ---------- | ------------ | ------------- | ------------ |
| 根 智能体 | 126,390      | 1,567         | 127,957      |
| 子智能体 A | 34,075       | 465           | 34,540       |
| 子智能体 B | 89,304       | 667           | 89,971       |

在这段录制的会话中，三个智能体的总数相加等于会话标题中显示的 **252,468 个 token** 会话标题中显示的数值。
