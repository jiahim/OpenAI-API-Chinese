# 追踪

> 有关完整文档索引，请参阅 [llms.txt](/llms.txt)。文档页面的 Markdown 版本可通过在页面 URL 后追加 `.md` 来获取。

一个 **会话** 让你的 智能体 的对话和工作保持在一起。一个会话可以包含多个 **轮次**，每一轮都是一次工作循环。一个 **追踪** 展示了一个轮次内的各个步骤：模型响应、工具调用，以及委派给其他 智能体 的工作。

该 [追踪 仪表板](https://platform.openai.com/logs?api=agents) 展示你的 智能体 执行的内容，包括每个步骤记录的输入、输出、耗时和状态。

关于会话状态、实时事件、已保存输出以及通过 API 的使用情况，请从 [可观测性](https://developers.openai.com/api/docs/guides/agents-api/observability).

默认情况下，新会话会启用追踪功能。你可以查看仪表板中的追踪，或者通过 API 导出它们。

## 打开追踪

1. 打开 [日志 → 智能体](https://platform.openai.com/logs?api=agents) 并选择你运行智能体的项目。
2. 通过以下方式找到你的会话 **搜索日志**。使用 **添加筛选条件** 按模型、状态或日期进行筛选。
3. 选择该会话以打开其时间线和轮次列表。
4. 展开一个轮次，然后在时间线或事件列表中选择一个步骤以查看其详细信息。

会话摘要会展示其状态、模型、开始时间、最近活动、轮次数量以及已记录的令牌使用情况。

## 阅读追踪

先从会话入手，再逐步了解一轮交互：

1. **Session（会话）：** Logs（日志）→ 智能体 中的每个条目都是一个会话。打开它可以查看其时间线以及轮次列表。例如，用户可以先询问订单相关信息，然后在同一会话中提出后续问题。
2. **Turn（轮次）：** 展开一个轮次即可查看该周期内执行的工作。一个轮次可以包含多个模型响应和工具调用。在该轮次结束后发送的后续消息将在同一会话中开启新的轮次。
3. **Steps within the turn（轮次内的步骤）：** 追踪 将模型响应和工具调用按执行它们的根 智能体 或子智能体进行分组。每条记录的步骤称为 **span**.

选择一个片段以查看其状态、持续时间、开始和结束时间以及记录的数据：

| Select                                           | 可查看的内容                                                           |
| ------------------------------------------------ | ------------------------------------------------------------------------------ |
| [**智能体**](#agent)                              | 智能体的详细信息、指令以及记录的 token 使用量                    |
| [**生成**](#generation) （模型响应） | 模型响应的输入与输出记录                             |
| [**工具**](#tool)                                | 调用的工具、传入的参数以及可用时的结果 |

### 智能体

智能体 span 将以下工作归为同一组： **根 智能体** 或 **子智能体**：由另一个被请求处理部分任务的 智能体。模型响应和工具调用会出现在执行它们的 智能体 下。

详细信息面板显示：

- **智能体类型：** 根 智能体（`root`）或子智能体（`subagent`).
- **智能体：** 记录时的 ID、名称、模型和指令。
- **使用情况：** 该 智能体 记录的 token 计数。这些计数仅涵盖 智能体 本身，不包括其子智能体。
- **持续时间** 和 **结果状态：** 记录的工作耗时以及它是已完成、失败还是未完成。

### 生成

生成跨度对记录的模型输入和输出进行分组。每个轮次可以包含多个生成。

在模型推理过程中，模型会读取其输入并生成响应。该响应可以请求工具。工具返回后，模型可以在新的生成中再次生成响应。

- **Input：** 与该响应关联的已记录输入，例如用户消息或工具结果。
- **Output：** 模型生成的已记录项，例如回答文本或工具调用。
- **Model：** 用于生成该响应的模型（如果已记录）。

### Tool

工具 span 用于描述一次工具调用及其记录的结果。

工具 span 包括对你自定义函数的调用，以及对 **MCP（Model Context Protocol）** 服务器上工具的调用。网页搜索和命令执行也可能以工具 span 的形式出现。

- **调用：** 工具请求，包括工具名称以及参数（若存在）。
- **结果：** 工具返回的记录响应（若可用）。
- **结果状态** 和 **错误：** 记录的结果与错误详情（若存在）。

对于 MCP 工具调用， **Call** 包含服务器标签（`server_label`）、工具名称（`name`）和参数（`arguments`）。其响应和错误会记录在该处的 `output` 和 `error`，中（如果可用）。独立的 **Result** 面板可能为空，因为 MCP 响应存储在 **Call**.

## 时机与状态

时间线展示了各个步骤的顺序以及哪些步骤是重叠的。 **放大** 以更详细地展示较短的步骤。 **适配时间线** 展示整个会话。

每个 span 都会显示其持续时长和结果状态。失败的 span 还可以包含已记录的错误详情。

一个 智能体 span 的持续时长包含其子步骤。步骤可以重叠：两个子智能体同时运行 10 秒，大约覆盖 10 秒的已用时间。

## Token 使用

**Tokens** 会话摘要中的 Tokens 表示该会话的使用量。 **Usage** 中显示的是该智能体跨度内该智能体记录的 token 数。

Usage 可能会在该轮结束后才到达。出现空值或 `null` 表示该数值未知，并不代表该智能体使用了零个 token。随着更多使用数据陆续到达，这些数值可能会发生变化，并不构成最终账单。

## 当追踪就绪时

追踪在轮次结束后构建。智能体的回答可能在其追踪或令牌使用情况尚未就绪时就已经出现。

[实时会话事件](https://developers.openai.com/api/docs/guides/agents-api/sessions/events) 会在智能体仍在工作时显示进度。

## 导出会话追踪

将会话追踪下载下来，以便在其他追踪工具中查看。该端点 `GET /v1/agents/sessions/{session_id}/traces` 会返回一页包含 OpenTelemetry Protocol (OTLP) JSON 的追踪。

必须为你的组织启用追踪导出。使用会话所在项目的API 密钥，并具备追踪读取权限（
  会话所在项目的（`api.traces.read`）或更广泛的
  智能体读取权限（`api.agents.read`).

设置 `OPENAI_API_KEY` 并将 `sess_123` 替换为你的会话 ID。本示例使用 cURL 和 `jq` 将其中一页保存为 `traces.otlp.json`:

下载一页会话追踪

```bash
curl --fail-with-body \
  "https://api.openai.com/v1/agents/sessions/sess_123/traces?limit=20&order=asc" \
  -H "Authorization: Bearer $OPENAI_API_KEY" \
  -H "OpenAI-Beta: agents=v1" \
  --output trace-page.json && \
jq '{resourceSpans: [.data[].otlp.resourceSpans[]]}' trace-page.json > traces.otlp.json
```


该命令会将该页中的追踪合并为一个 OTLP 载荷。使用你的追踪提供方的身份认证，将其发送到该提供方的 OTLP/HTTP 端点。

若要导出整个会话，请检查 `trace-page.json`。当 `has_more` 为 `true`，时，使用 `last_id` 作为 `after`，请求下一页， `order`。保持不变。在获取下一页之前先保存或上传每一页，并重复该过程，直到 `has_more` 为 `false`.

导出仅包含你在每次发起请求时可用的追踪。若要进行历史导出，请等待该会话的所有轮次完成，并预留时间让追踪出现。导出操作不会为未来的追踪建立自动推送。

### 导出智能体的追踪

要跨智能体的会话导出追踪，首先 [列出会话](https://developers.openai.com/api/docs/guides/agents-api/sessions/manage#find-sessions) 然后使用 `agent_id` 筛选条件。将其替换为你的智能体 ID： `agent_123` with your 智能体's ID:

查找某智能体的会话

```bash
curl --fail-with-body \
  "https://api.openai.com/v1/agents/sessions?agent_id=agent_123&limit=100&order=asc" \
  -H "Authorization: Bearer $OPENAI_API_KEY" \
  -H "OpenAI-Beta: agents=v1"
```


1. 对于每个会话，使用其 `data`，按上文所述导出该会话追踪的每一页 `id` 。
2. 当会话列表包含 `has_more: true`，时，将该列表的 `last_id` 作为 `after` 传入以获取下一页。保持相同的 `agent_id` 和 `order`.
3. 重复此过程，直到会话列表包含 `has_more: false`.

该筛选器会匹配会话的根智能体。请将会话列表游标与会话各自的追踪游标分开保存。

## 示例：包含两个子智能体的一次轮次

本示例基于一次录制的会话。根智能体调用一个 MCP 工具，同时两个子智能体运行命令并获取文档。下文中的子智能体名称经过简化；计数和耗时来自录制的追踪。

### 会话与轮次

会话标头显示 **1 个回合**, **10 次工具调用**，以及 **252,468 个 tokens**。会话状态为 **空闲**，以及 **回合 1** 为 **已完成** ，持续时间为 **1 分 37 秒**.

展开该回合可看到根智能体及其子步骤。该追踪包含 **3 个智能体跨度** （根智能体和两个子智能体）， **11 个生成跨度**，以及 **10 个工具跨度**.

该树将重复的生成和工具调用归为一组，显示父级关系；时间线则展示每个步骤的运行时间。

```text
Session: Idle
└── Turn 1: Completed                              1m 37s
    └── Root agent                                1m 37s
        ├── 6 generations
        ├── 2 tools: spawn_agent_call
        ├── Subagent A                               24s
        │   ├── 2 generations
        │   └── Tool: command_execution               2s
        ├── Subagent B                               21s
        │   ├── 3 generations
        │   ├── 2 tools: notion.fetch              2s each
        │   └── Tool: send_input_call                 0ms
        ├── Tool: demo_capability_probe              87ms
        └── 3 tools: wait_for_agents_call
```

### 模型工作与委托

根智能体的第一次 **生成** 在 **输入**。中包含用户消息。它的 **输出** 包含消息和两个 `spawn_agent_call` 条目。这些调用也会作为 **工具** span 出现，产生的子智能体作为 **智能体** span 出现在根节点下。

子智能体 A 有自己的生成和一次 `command_execution` 工具调用。子智能体 B 有三次生成、两次 `notion.fetch` MCP 调用，以及一次 `send_input_call`。它们的模型响应和工具属于各自对应的子智能体 span。

根智能体也有三个 `wait_for_agents_call` 工具 span。它的最后一次生成包含一条消息，记录的耗时为 **6s**.

### MCP 工具调用

根 智能体 的 `demo_capability_probe` span 是一条已完成的 **工具** span，持续时间为 **87ms**。中包含用户消息。它的 **工具类型** 为 `mcp_call`.

该 **Call** 面板包含这些字段：

```json
{
  "type": "mcp_call",
  "server_label": "demo_local",
  "name": "demo_capability_probe",
  "status": "completed"
}
```

此片段展示了所记录调用的一部分。同一个面板还包含其 `arguments` 以及位于 `output`。中的 MCP 响应。独立的 **Result** 面板为 `null`。该 span 的 **父 span** 指向根 智能体。

子智能体 B 的两条 `notion.fetch` span 具有相同的结构： `mcp_call` 作为工具类型，位于 **Call**，中的 MCP 响应，以及作为其父级的子智能体。

### 本次会话的时序与用量

两个子智能体的时间段在时间轴上重叠。子智能体 A 用时 **24 秒** ，子智能体 B 用时 **21 秒**，既包括根 智能体 内部的 **1 分 37 秒** 跨度。仪表板会对这些显示的持续时间进行取整。

该 **Usage** 面板会在每个 智能体 跨度上显示其各自记录的 token 数量：

| 智能体      | 输入令牌数 | 输出令牌数 | 令牌总数 |
| ---------- | ------------ | ------------- | ------------ |
| 根智能体 | 126,390      | 1,567         | 127,957      |
| 子智能体 A | 34,075       | 465           | 34,540       |
| 子智能体 B | 89,304       | 667           | 89,971       |

在这段录制的会话中，三个智能体的总数加起来等于会话标头中显示的 **252,468 个 tokens** 会话标头中显示的数字。
