## 如何理解模型与推理力度



  Luna 是最具成本效益的模型，而 Astra 是我们最先进、最强大的模型，
  如果你并不在意成本和延迟，可以默认使用
  Astra。若要降低成本或延迟，请参考以下指南选择适合你需求的模型
  和推理强度。





1. **Luna · Low**

   精细化编辑、范围明确的问题求解以及简单的数据提取。

2. **Luna · Extra high**

   跨多个应用获取最新上下文、安排工作优先级，并解决约束明确的问题。

3. **GPT-6.1 Sol · Medium**

   你预期会反复修改的复杂技术工作和需协调的交付物。

4. **GPT-6.1 Sol · Extra high**

   打磨完善的交付物、相互贯通的视觉体系，以及在相互冲突的证据中做出的决策。

5. **Astra · Low**

   保持事实与细微差别的简洁写作和内容改写。

6. **Astra · Medium**

   需要广泛上下文、稳定交互和完整成果的雄心勃勃的项目。

7. **Astra · Extra high**

   要求严苛的分析和标准极高的复杂交付物。

### 实验

请将本页面中的指引视为起点。要找到适合你的
工作流工作流的模型，最好的方法是尝试不同的模型和推理
设置，看看哪种最有效。

首先考虑以下几点：

- **你的工作流运行频率是多少？** 频繁运行的自动化比偶尔使用的项目
  更快地累积使用量和成本。
- **你需要多快拿到结果？** 你正在等待的任务可能需要比
  通宵运行的任务更快的设置。
- **你打算如何使用输出结果？** 供你审阅的草稿所需的润色可能少于
  你要对外分享的内容。
- **结果的质量有多重要？** 根据你的用例或所在
  行业，你可能希望使用更强大的模型来强调质量。

如果可以的话，使用相同的输入进行实验以比较结果，并保持
满足你质量标准的最低设置。
