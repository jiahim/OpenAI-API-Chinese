# 模型选择

> 如需查看完整的文档索引，请参阅 [llms.txt](/llms.txt)。文档页面的 Markdown 版本可通过在页面 URL 后追加 `.md` 来获取。

选择合适的模型，无论是 [`gpt-5.6`](https://developers.openai.com/api/docs/models/gpt-5.6-sol) 还是更小的选项（如 [`gpt-5.6-terra`](https://developers.openai.com/api/docs/models/gpt-5.6-terra)），都需要在 **准确性**, **延迟**和 **成本**之间做出权衡。本指南解释了关键原则并提供了一个实用示例，帮助你做出明智的决策。

## 核心原则

模型选择的原则很简单：

- **首先以准确性为优化目标：** 在达到准确性目标之前，持续以准确性为优化目标。
- **其次，再以成本和延迟为优化目标：** 然后，在保持准确性的前提下，尽可能使用最便宜、最快的模型。

### 1. 准确性优先

首先，为你的使用场景设定一个明确的准确性目标，明确对该场景而言“足够好”并可以投入生产的准确性水平。你可以通过以下方式实现这一点：

- **设定明确的准确率目标：** 确定你的目标准确率统计指标。
  - 例如，90% 的客户服务电话需要在首次交互时被正确分诊。
- **开发评估数据集：** 创建一个数据集，使你能够衡量模型在这些目标上的表现。
  - 扩展上述示例，捕获 100 个交互示例，其中包含用户请求的内容、LLM 将其分诊到的类别、正确的分诊结果，以及是否正确。
- **使用最强大的模型进行优化：** 从可用的最强大模型开始，以达到你的准确率目标。记录所有响应，以便我们将其用于蒸馏出更小的模型。
  - 使用检索增强生成来优化准确率
  - 使用微调来优化一致性和行为

在此过程中，收集提示和完成对，用于评估、少样本学习或微调。这种实践被称为 **提示烘焙**，有助于你为未来使用制作高质量的示例。

如需了解更多方法和工具，请参阅我们的 [准确性优化指南](https://developers.openai.com/api/docs/guides/optimizing-llm-accuracy).

#### 设定一个现实的准确度目标

通过评估模型决策的财务影响来计算现实可行的准确率目标。例如，在假新闻分类场景中：

- **正确分类的新闻：** 如果模型正确分类，它会为你节约人工审核的成本——假设 **$50**.
- **错误分类的新闻：** 如果模型将安全文章误判，或漏掉虚假新闻文章，则可能引发审核流程及潜在的投诉，或会造成 **$300**.

我们的新闻分类示例需要 **85.8%** 的准确率才能覆盖成本，因此设定 90% 或更高的目标可确保整体投资回报。使用这些计算，根据你的具体成本结构设定有效的准确率目标。

### 2. 优化成本与延迟

成本和延迟被认为是次要的，因为如果模型无法达到你的准确性目标，那么这些顾虑就毫无意义。然而，一旦你拥有了适合你的用例的模型，你可以采取以下两种方法之一：

- **与较小的模型进行零样本或少样本比较：** 将模型替换为更小、更便宜的模型，测试其在更低成本和延迟下是否保持准确性。
- **模型蒸馏：** 使用准确性优化期间收集的数据对较小模型进行微调。

成本和延迟通常相互关联；减少令牌和请求通常会导致更快的处理。

这里需要考虑的主要策略有：

- **减少请求次数：** 限制完成任务所需的必要请求数量。
- **最小化令牌数：** 降低输入令牌数量，并优化以缩短模型输出。
- **选择更小的模型：** 使用在降低成本与延迟的同时保持准确性的模型。

如需深入了解这些内容，请参阅我们的指南： [延迟优化](https://developers.openai.com/api/docs/guides/latency-optimization).

#### 该规则的例外情况

这些原则存在明显的例外情况。如果你的用例对成本或延迟极其敏感，请在开始测试之前为这些指标设定阈值，然后将超出这些阈值的模型从考虑中移除。一旦基准设定，这些指南将帮助你在约束范围内优化模型准确性。

## 实际示例

为演示这些原则，我们将开发一个具有以下目标指标的假新闻分类器。下面的实验使用历史 GPT-4o 系列结果来展示工作流；对于当前评估，请从 [`gpt-5.6`](https://developers.openai.com/api/docs/models/gpt-5.6-sol) 开始，并与更小或微调模型进行比较。

- **准确性：** 达到 90% 的正确分类
- **成本：** 每 1,000 篇文章花费低于 5 美元
- **延迟：** 将每篇文章的处理时间保持在 2 秒以内

### 实验

我们进行了三项实验来实现我们的目标：

1. **零样本：** 使用 `GPT-4o` 基础提示词处理了 1,000 条记录，但未达到准确率目标。
2. **少样本学习：** 包含了 5 个少样本示例，达到了准确率目标，但由于提示词 token 增多导致成本超支。
3. **微调模型：** 微调 `GPT-4o-mini` 使用了 1,000 个带标签的示例，以相似的延迟和准确率达成了所有目标，且成本显著降低。

| ID  | 方法                                  | 准确性 | 准确性目标 | 成本   | 成本目标 | 平均延迟 | 延迟目标 |
| --- | --------------------------------------- | -------- | --------------- | ------ | ----------- | ------------ | -------------- |
| 1   | gpt-4o zero-shot                        | 84.5%    |                 | $1.72  |             | < 1s         |                |
| 2   | gpt-4o few-shot (n=5)                   | 91.5%    | ✓               | $11.92 |             | < 1s         | ✓              |
| 3   | gpt-4o-mini fine-tuned w/ 1000 examples | 91.5%    | ✓               | $0.21  | ✓           | < 1s         | ✓              |

## 结论

通过从 `gpt-4o` 切换到 `gpt-4o-mini` 并使用微调，我们实现了 **以不到 2% 的成本获得等效性能** ，仅使用了 1,000 个标注示例。

这一过程很重要——你通常无法直接进行微调，因为你不确定微调是否是实现所需优化的正确工具，或者你没有足够的标注示例。先从 [`gpt-5.6`](https://developers.openai.com/api/docs/models/gpt-5.6-sol) 开始以确定你的准确率目标，然后在成本和延迟重要时测试更小或微调后的模型。
