# 模型选择

> 如需查看完整文档索引，请参阅 [llms.txt](/llms.txt)。可通过在页面 URL 末尾追加 `.md` 来获取文档页面的 Markdown 版本。

选择合适的模型，无论 [`gpt-6-astra`](https://developers.openai.com/api/docs/models/gpt-6-astra) 还是像 [`gpt-5.6-terra`](https://developers.openai.com/api/docs/models/gpt-5.6-terra)，这样更小的选项，都需要在 **准确性**, **延迟**，和 **成本**。之间进行权衡。本指南将介绍一些关键原则，帮助你做出明智的决策，并提供一个实用示例。

## 核心原则

模型选择的原则很简单：

- **首先优化准确性：** 在达到准确性目标之前，优先优化准确性。
- **其次优化成本和延迟：** 然后在保持准确性的前提下，使用尽可能便宜且速度最快的模型。

### 1. 准确性优先

首先为你的用例设定一个明确的准确率目标，明确该用例上线所需的“足够好”的准确率。你可以通过以下方式实现：

- **设定明确的准确率目标：** 明确你的目标准确率统计指标。
  - 例如，90% 的客服电话需要在首次交互时被正确分类。
- **构建评估数据集：** 创建一个数据集，使你能够根据这些目标衡量模型的性能。
  - 在上述示例基础上，采集 100 个交互样本，其中包含用户提出的问题、LLM 将其分类到哪个类别、正确的分类结果，以及此次分类是否正确。
- **使用最强模型进行优化：** 从可用的最强模型入手，以达成你的准确率目标。记录所有响应，以便用于蒸馏出更小的模型。
  - 使用检索增强生成来优化准确率
  - 使用微调来优化一致性和行为

在此过程中，收集 prompt 与 completion 配对，用于评估、少样本学习或微调。这种做法被称为 **prompt 烘焙**，可帮助你生成高质量的示例供后续使用。

了解更多相关方法和工具，请参阅我们的 [准确度优化指南](https://developers.openai.com/api/docs/guides/optimizing-llm-accuracy).

#### 设定切实可行的准确率目标

通过评估模型决策的财务影响来设定一个合理的准确性目标。例如，在一个虚假新闻分类场景中：

- **正确分类的新闻：** 如果模型分类正确，可以节省人工审核的成本，假设为 **$50**.
- **错误分类的新闻：** 如果它将一篇安全的文章错误分类，或漏掉一篇假新闻文章，可能会触发审核流程并引发投诉，由此产生的费用可能是 **$300**.

我们的新闻分类示例需要 **85.8%** 的准确率才能覆盖成本，因此将目标设定在 90% 或以上可确保整体投资回报。利用这些计算结果，根据你自身的成本结构设定一个有效的准确率目标。

### 2. 优化成本和延迟

成本和延迟被视为次要因素，因为如果模型无法达到你的准确率目标，这些考量便毫无意义。然而，一旦找到适用于你用例的模型，你可以采取以下两种方法之一：

- **与较小的零样本或少样本模型进行比较：** 将模型替换为更小、更便宜的版本，并测试它在更低成本和更低延迟下是否能保持准确率。
- **模型蒸馏：** 使用在准确率优化过程中收集的数据对较小的模型进行微调。

成本和延迟通常是相互关联的；减少 token 和请求通常会带来更快的处理速度。

这里可以考虑的主要策略包括：

- **减少请求次数：** 限制完成任务所需的请求数量。
- **最小化 token：** 降低输入 token 数量，并优化以获得更短的模型输出。
- **选择更小的模型：** 使用在降低成本与延迟的同时保持准确性的模型。

要深入了解这些内容，请参阅我们的指南： [延迟优化](https://developers.openai.com/api/docs/guides/latency-optimization).

#### 例外情况

这些原则也存在明确的例外。如果你的用例对成本或延迟极为敏感，请在开始测试之前为这些指标设定阈值，然后将超出阈值的模型从候选中剔除。一旦设定了基准，这些指南将帮助你在既定约束范围内优化模型准确性。

## 实用示例

为了展示这些原则，我们将开发一个假新闻分类器，并设定以下目标指标。下面的实验使用历史 GPT-4o 系列的结果来展示该工作流；若要查看当前的评估结果，请从 [`gpt-6-astra`](https://developers.openai.com/api/docs/models/gpt-6-astra) 开始，并将其与更小的模型或微调后的模型进行比较。

- **准确性：** 实现 90% 的正确分类
- **成本：** 每 1,000 篇文章的花费低于 5 美元
- **延迟：** 每篇文章的处理时间保持在 2 秒以内

### 实验

为实现我们的目标，我们进行了三次实验：

1. **零样本：** 对 1,000 条记录使用 `GPT-4o` 基础提示词，但未达到准确率目标。
2. **少样本学习：** 包含 5 个少样本示例，达到了准确率目标，但由于提示词 token 更多，超出了成本。
3. **微调模型：** 使用 1,000 条 `GPT-4o-mini` 已标注示例进行了微调，在延迟和准确率相近的情况下达到了所有目标，但成本显著降低。

| ID  | 方法                                  | 准确率 | 准确率目标 | 成本   | 成本目标 | 平均延迟 | 延迟目标 |
| --- | --------------------------------------- | -------- | --------------- | ------ | ----------- | ------------ | -------------- |
| 1   | gpt-4o zero-shot                        | 84.5%    |                 | $1.72  |             | < 1s         |                |
| 2   | gpt-4o few-shot (n=5)                   | 91.5%    | ✓               | $11.92 |             | < 1s         | ✓              |
| 3   | gpt-4o-mini fine-tuned w/ 1000 examples | 91.5%    | ✓               | $0.21  | ✓           | < 1s         | ✓              |

## 结论

通过从 `gpt-4o` 切换到 `gpt-4o-mini` 并进行微调，我们实现了 **相当的性能，成本却不到 2%** 仅使用了 1,000 个标注样本。

这一过程很重要——你通常无法直接跳到微调，因为你不知道微调是否是你所需优化的合适工具，或者你没有足够的标注样本。可以先从 [`gpt-6-astra`](https://developers.openai.com/api/docs/models/gpt-6-astra) 入手，设定你的准确性目标，然后在成本和延迟成为关键因素时，再测试更小的模型或微调后的模型。
