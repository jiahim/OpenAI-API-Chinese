## 如何理解模型与推理力度



  Luna 是性价比最高的模型，而 Astra 是我们最先进、最强大的模型，
  如果成本和延迟不是问题，你可以默认使用
  Astra。如需降低成本或延迟，可参考以下指南，为你的需求选择合适的模型
  和推理强度。





1. **Luna · 低**

   精细化编辑、范围明确的问题解答以及简单的数据抽取。

2. **Luna · 中**

   根据清晰的简报创建内容，并对现有工作进行协调一致的更新。

3. **Luna · 超高**

   跨多个应用获取当前上下文、安排工作优先级，并在明确约束下解决问题。

4. **Sol · 低**

   聚焦的写作与编辑、事实核查，以及在应用中处理日常事务。

5. **Sol · 中**

   需要判断力与完整性的日常编码、研究和工作流。

6. **Sol · 超高**

   更深入的分析、全面的核实，以及对文档、数据和代码的细致审阅。

7. **Astra · 低**

   保持事实与细微差别的简洁写作与内容改编。

8. **Astra · 中**

   需要广泛上下文、可靠交互和完整成果的宏大项目。

9. **Astra · 超高**

   要求严苛的分析与具有严格标准的复杂交付物。

### Experiment

将本页指南视为一个起点。要找到适合你的
工作流的模型，最佳方式是尝试不同的模型和推理
设置，看看哪种效果最好。

首先考虑：

- **你的工作流运行频率如何？** 频繁的自动化任务比偶尔使用的项目
  更快地累积使用量和成本。
- **你需要多快得到结果？** 你正在等待的任务可能需要比
  通宵运行的任务更快的设置。
- **你将如何使用输出？** 供你审阅的草稿所需的润色
  可能少于你对外分享的内容。
- **结果的质量有多重要？** 根据你的用例或
  所在行业，你可能希望使用更强的模型来强调质量。

如果可以，请尝试使用相同的输入来比较结果，并保留满足你质量要求的
最轻量设置。
