# Model selection

> 如需查看完整文档索引，请参阅 [llms.txt](/llms.txt)。可通过在页面 URL 后追加 `.md` 来获取文档页面的 Markdown 版本。

选择合适的模型，无论是 [`gpt-5.6`](https://developers.openai.com/api/docs/models/gpt-5.6-sol) 还是更小的选项例如 [`gpt-5.6-terra`](https://developers.openai.com/api/docs/models/gpt-5.6-terra)，都需要在 **准确度**, **延迟**，和 **成本**。之间做出权衡。本指南解释了关键原则，帮助你做出明智的决策，并提供了一个实用示例。

## 核心原则

模型选择的原则很简单：

- **首先优化准确性：** 在达到准确性目标之前，持续优化准确性。
- **其次优化成本和延迟：** 然后在保持准确性的同时，尽可能选择最便宜、最快的模型。

### 1. 优先保证准确性

首先为你的用例设定一个明确的准确率目标，明确在该用例投入生产所需的“足够好”的准确率。你可以通过以下方式实现：

- **设定明确的准确率目标：** 明确你将要使用的目标准确率统计指标。
  - 例如，90% 的客户服务呼叫需要在首次交互时被正确分流。
- **构建评估数据集：** 创建一个数据集，使你能够衡量模型相对于这些目标的性能。
  - 延用上面的示例，采集 100 个交互样本，其中包括用户提出的需求、LLM 分流到的结果、正确的分流应该是怎样的，以及该结果是否正确。
- **使用能力最强的模型进行优化：** 从可用的能力最强的模型开始，以达成你的准确率目标。记录所有响应，以便我们将其用于蒸馏出更小的模型。
  - 使用检索增强生成来优化准确率
  - 使用微调来优化一致性和行为表现

在此过程中，收集提示词与补全结果，用于评估、少样本学习或微调。这一做法被称为 **prompt baking**，可帮助你生成高质量的示例供后续使用。

如需了解更多信息和工具，请参阅我们的 [准确性优化指南](https://developers.openai.com/api/docs/guides/optimizing-llm-accuracy).

#### 设定切合实际的准确性目标

通过评估模型决策的财务影响来设定一个切实可行的准确率目标。例如，在假新闻分类场景中：

- **正确分类的新闻：** 如果模型将其正确分类，就省去了人工审核的成本 —— 假设为 **$50**.
- **错误分类的新闻：** 如果它将一篇安全的文章错误地分类，或漏掉一篇假新闻文章，就可能触发审核流程和潜在的投诉，这可能让我们花费 **$300**.

我们的新闻分类示例需要 **85.8%** 的准确率才能覆盖成本，因此以 90% 或更高为目标可确保整体投资回报。利用这些计算结果，根据你具体的成本结构设定一个有效的准确率目标。

### 2. 优化成本与延迟

成本和延迟被视为次要因素，因为如果模型达不到你的准确性目标，这些考量便毫无意义。不过，一旦你找到适合你用例的模型，可以采取以下两种方法之一：

- **与更小的模型进行零样本或少样本对比：** 将模型替换为更小、更便宜的版本，并测试其在更低成本和延迟下是否能保持准确率。
- **模型蒸馏：** 使用准确率优化过程中收集的数据对较小的模型进行微调。

成本与延迟通常相互关联；减少 token 和请求数量通常会带来更快的处理速度。

这里可以考虑的主要策略包括：

- **减少请求次数：** 限制完成任务所需的请求数量。
- **最小化 token 使用：** 减少输入 token 数量，并优化模型输出，使其更简短。
- **选择更小的模型：** 使用在降低成本和延迟的同时仍能保持准确性的模型。

如需深入了解这些内容，请参阅我们的 [延迟优化](https://developers.openai.com/api/docs/guides/latency-optimization).

#### 例外情况

这些原则也存在明显的例外。如果你的用例对成本或延迟极为敏感，请在开始测试前为这些指标设定阈值，然后将超出阈值的模型从候选中剔除。一旦设定了基准，这些准则就能帮助你在约束范围内提升模型的准确率。

## 实际示例

为了演示这些原则，我们将开发一个假新闻分类器，并设定以下目标指标。下面的实验使用历史 GPT-4o 系列的结果来展示 工作流；如需当前的评估结果，请从 [`gpt-5.6`](https://developers.openai.com/api/docs/models/gpt-5.6-sol) 并与更小的模型或微调后的模型进行比较。

- **准确率：** 实现 90% 的正确分类
- **成本：** 每 1,000 篇文章花费不超过 $5
- **延迟：** 每篇文章的处理时间保持在 2 秒以内

### 实验

为达成目标，我们开展了三项实验：

1. **零样本：** 使用基础提示处理 1,000 条记录 `GPT-4o` 但未达到准确率目标。
2. **少样本学习：** 包含 5 个少样本示例，达到了准确率目标，但由于提示词 token 更多，成本超出预期。
3. **微调模型：** 使用 1,000 条标注示例进行微调 `GPT-4o-mini` 在延迟和准确率相近的情况下达到了所有目标，同时成本显著降低。

| ID  | 方法                                  | 准确率 | 准确率目标 | 成本   | 成本目标 | 平均延迟 | 延迟目标 |
| --- | --------------------------------------- | -------- | --------------- | ------ | ----------- | ------------ | -------------- |
| 1   | gpt-4o zero-shot                        | 84.5%    |                 | $1.72  |             | < 1s         |                |
| 2   | gpt-4o few-shot (n=5)                   | 91.5%    | ✓               | $11.92 |             | < 1s         | ✓              |
| 3   | gpt-4o-mini fine-tuned w/ 1000 examples | 91.5%    | ✓               | $0.21  | ✓           | < 1s         | ✓              |

## 结论

通过从 `gpt-4o` 切换到 `gpt-4o-mini` 进行微调，我们以 **不到 2% 的成本达到了同等性能%** ，仅使用了 1,000 个标注样本。

这一过程非常重要——你通常无法直接跳到微调，因为你不知道微调是否是你所需优化的合适工具，或者你没有足够的标注样本。先使用 [`gpt-5.6`](https://developers.openai.com/api/docs/models/gpt-5.6-sol) 来确立你的准确性目标，然后在成本和延迟成为关键因素时，再测试更小的或经过微调的模型。
