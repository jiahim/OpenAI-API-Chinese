# 在 OpenAI 平台中管理权限

> 如需完整的文档索引，请参阅 [llms.txt](/llms.txt)。文档页面的 Markdown 版本可通过在页面 URL 后追加 `.md` 来获取。

基于角色的访问控制（RBAC）让你可以决定谁能在你的组织和项目中执行哪些操作——无论是通过 API 还是在 Dashboard 中。相同的权限同时管控这两个界面：如果某人可以调用某个端点（例如， `/v1/chat/completions`），他们就可以使用对应的 Dashboard 页面，而缺失的权限会禁用相关 UI（例如 **Upload** 按钮在 Playground 中）。使用 RBAC，你可以：

- 大规模分组用户并分配权限
- 创建具有你所需确切权限的自定义角色
- 在组织或项目级别限定访问范围
- 在仪表板和API中强制执行一致的权限

## 关键概念

- **组织**：你的顶级账户。组织角色可以授予跨所有项目的访问权限。
- **项目**：用于密钥、文件和资源的工作区。项目角色仅授予该项目的访问权限。
- **用户组**：你可以为其分配角色的用户集合。用户组可以从你的身份提供商（通过 SCIM）同步，以自动保持成员资格的最新状态。
- **角色**：权限的集合（如模型请求或文件写入）。可以在 **组织设置**，下为组织创建角色，或在该项目的设置下为特定项目创建角色。创建后，组织或项目角色可以分配给用户或用户组。用户可以拥有多个角色，其访问权限是这些角色的并集。
- **权限**：角色允许的特定操作（例如，向模型发出请求、读取文件、写入文件、管理密钥）。

#### 批量权限影响

批处理权限包括准备批处理输入文件、执行请求及检索结果所需的访问权限。此有效访问权限与可在批处理内部提交的端点（这些端点在 [批处理 API 指南](https://developers.openai.com/api/docs/guides/batch#1-prepare-your-batch-file).

| 批处理权限          | 附加访问权限                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 读取（`api.batch.read`)   | 文件读取（`api.files.read`），用于 `/v1/files`                                                                                                                                                                                                                                                                                                                                                                                                                        |
| 写入（`api.batch.write`) | 批处理读取<br />列出模型（`api.model.read` 和 `model.read`），用于 `/v1/models`<br />文件读写（`api.files.read` 和 `api.files.write`），用于 `/v1/files`<br />模型能力请求（`api.model.request` 和 `model.request`），用于 `/v1/audio`, `/v1/chat/completions`, `/v1/embeddings`, `/v1/images`, `/v1/moderations`, `/v1/realtime`，以及 `/v1/responses`<br />视频读写（`api.videos.read` 和 `api.videos.write`），用于 `/v1/videos` |

## 设置 RBAC

允许最多 **30 分钟** 以供角色变更和组同步生效。

1. **创建群组**
   为团队添加群组（例如，“数据科学”“支持”）。如果你使用 IdP，请启用 SCIM 同步，以便群组成员资格保持最新。

2. **创建自定义角色**
   从最小权限开始。例如：
   - _模型测试员_：模型读取、模型功能请求、评估
   - _模型工程师_：模型功能请求、文件读/写、微调
   - _应用发布者_：应用读取、应用写入

3. **分配角色**
   - **组织级别** 角色适用于所有位置（组织内的所有项目）。
   - **项目级别** 角色仅适用于该项目。
     你可以将角色分配给 **用户** 和 **群组**。用户可持有多个角色；访问权限是 **联合**.

4. **验证**
   使用非所有者账户确认预期访问权限（API 和 Dashboard）。如果用户看到的超出其所需，请调整角色。

遵循最小权限原则。首先分配任务所需的最低权限
  ，然后仅在需要时添加更多权限。

## 访问配置示例

### 小团队

- 为核心团队赋予组织级角色，包含模型能力请求和文件读写权限。
- 为每个应用创建项目；仅将承包商添加到这些项目中，并赋予项目级角色。

### Larger org

- 从你的 IdP 同步群组（例如“研究”“支持”“财务”）。
- 按职能创建自定义角色并在组织级别分配；或仅在项目需要更严格的控制时授予项目特定角色。

### 承包商与供应商

- 创建一个“承包商”群组，不为其分配组织级角色。
- 将他们添加到特定项目，并赋予范围狭窄的项目角色（例如，只读访问权限）。

## 用户访问的评估方式

在仪表盘中，我们结合了：

- 来自 **组织** （直接 + 通过群组）
- 来自 **项目** （直接 + 通过群组）

有效权限是 **并集** 所有已分配角色。

如果在项目中使用 API 密钥请求，我们会采用分配给该 API 密钥的权限，并确保用户拥有授予这些权限的项目角色。例如，如果请求 /v1/models，则 API 密钥必须具有 api.model.read 权限，且用户必须拥有包含 api.model.read 的项目角色。

## 最佳实践

- **按群组为你的组织建模**：在 IdP 中镜像团队，并将角色分配给群组而非个人。
- **职责分离**：读取模型与上传文件与管理密钥分开。
- **项目边界**：将实验、预发和生产环境放在不同的项目中。
- **定期审查**：移除未使用的角色和密钥；轮换敏感密钥。
- **以非所有者身份测试**：在全面推广之前验证访问权限是否符合预期。
